# HP 能量条设计需求与协议边界

本文档面向负责设计「个人 HP（精力/肉体能量）」数据来源与计算方案的下游设计者/Agent，仅说明**设计需求**与**本显示系统的协议边界**。

---

## 一、设计需求

需要在 `Claude / Codex / Grok / Gemini / Bandwagon` 等 AI 与服务配额之前，提供一个代表**个人当前精力/体力剩余（HP）**的进度条。上游方案需完成以下设计：

1. **数据源选型**
   - 明确输入信号来源及获取方式（例如 Apple Health 睡眠/HRV/静息心率/活动量、穿戴设备、日程/专注时长、手动打卡，或上述组合）。
   - 明确在部分信号缺失（如某天未佩戴设备、未同步健康数据）时的降级策略，不伪造虚假满值或零值。
2. **HP 计算与演化规则（0–100）**
   - 定义初始值/基准值来源、日间消耗（`draining`）、休息/睡眠/运动恢复（`charging`）与平稳期（`steady`）的计算方式。
   - 输出结果映射为 `0–100` 的剩余百分比（`100` = 满状态，`0` = 耗尽，无法计算时输出 `null`）。
3. **短状态文案设计**
   - 为不同状态/分数段定义简短中文状态词（`status`）与可选说明（`note`），适配小屏单行展示（详见下方长度约束）。
4. **更新频率与有效期**
   - 明确数据产生/推送节奏，并据此确定合理的 `stale_after_seconds`，避免低频健康数据被过早判为「已过期」，也避免过期旧值长期伪装为新鲜数据。
5. **写入方式**
   - 明确采用外部主动推送（`PUT /v1/energy`）还是接入服务端按需采集调度（Collector 协议）。

---

## 二、本程序协议边界

### 2.1 职责边界
- **本系统负责**：持久化存储最新一条 `energy` 数据、字段校验、独立有效期判定、将 `energy` 自动投影为展示列表首位项并下发给各显示终端（iPhone StandIt、ESP32-S3 方屏、HoloCubic 小屏）。
- **本系统不负责**：不采集任何生理/健康/作息数据，不做 HP 评分或随时间自动衰减/回血计算，也不维护历史趋势曲线。
- **零客户端改动**：遵循本协议推送即可在所有终端动态生效，无需修改或重装任何客户端/固件。

### 2.2 写入与清除接口
- **服务地址**：本机 `http://127.0.0.1:8007`（frp 出口 `http://120.48.136.92:8007`）
- **鉴权**：`Authorization: Bearer <DISPLAY_WRITE_TOKEN>`（写权限 token，位于 `server/display.env`；只读 token 与消息/Bot token 均无权写入，返回 `403`）
- **请求限制**：UTF-8 JSON，请求体上限 `64 KB`
- **接口**：
  - `PUT /v1/energy`：写入或覆盖当前 HP 数据；请求体为 `null` 时等价于清空。成功返回 `200` 及清洗后的 `{"energy": ..., "collection": ...}`；校验失败返回 `400`，不覆盖已有数据。
  - `DELETE /v1/energy`：清空当前 HP 数据（服务端置为 `null`，全端自动隐藏）。成功返回 `200 {"energy": null}`。
- **可选命令行封装**：`server/energy_usage.py` 已封装 `PUT / DELETE /v1/energy`（自动读取 `DISPLAY_WRITE_TOKEN`）。

### 2.3 数据契约与校验规则

```json
{
  "name": "HP",
  "level_percent": 65,
  "status": "正常",
  "trend": "draining",
  "note": "下午专注",
  "source": "estimated",
  "updated_at": 1795601045,
  "stale_after_seconds": 14400
}
```

| 字段 | 类型 | 必填 | 约束与服务端处理 |
|---|---|---|---|
| `name` | string | 否 | 去首尾空白后截断至 `40` 字符；缺省为 `"HP"` |
| `level_percent` | number \| `null` | 否 | 剩余百分比，超出 `[0, 100]` 会被截断到边界，保留最多 1 位小数（整数输出为 int）；布尔值/非数字/NaN/Inf 返回 `400`；`null` 或省略显示 `--` |
| `status` | string | 否 | 截断至 `16` 字符；空字符串视为省略 |
| `trend` | string \| `null` | 否 | 仅允许 `"charging"` / `"draining"` / `"steady"`，其他值返回 `400` |
| `note` | string | 否 | 截断至 `80` 字符；空字符串视为省略 |
| `source` | string | 否 | 仅允许 `"official"` / `"manual"` / `"estimated"` / `"unknown"`，缺省 `"unknown"`，非法值返回 `400` |
| `updated_at` | int | 否 | Unix **秒**（大于 `1e11` 的毫秒值返回 `400`）；缺省由服务端补收到请求时的时间戳；响应自动附带 `updated_at_utc` |
| `stale_after_seconds` | int | 否 | 范围 `60`–`604800`（1 分钟至 7 天），非整数/布尔值/越界返回 `400`；缺省沿用全局 `stale_after_seconds`（默认 `900` 秒） |

### 2.4 服务端投影与有效期边界
- **显隐规则**：`energy` 为非空对象时，服务端在响应 `GET /v1/display` 时自动将其投影为 `subscriptions[0]`（`id: "energy"`，排位优先于所有订阅）；`energy` 为 `null` 时不投影，全端自动隐藏。
- **百分比换算**：服务端将 `level_percent` 换算为展示协议的 `used_percent = round(100 - level_percent, 1)`，终端再以 `floor(100 - used_percent)%` 渲染进度条宽度与数字。
- **标签拼装与 16 字上限**：
  - 基础标签优先取 `status`；若省略则按 `trend` 映射（`charging` → `"回血中"`、`draining` → `"消耗中"`、`steady` → `"平稳"`）；均省略则取 `"当前"`。
  - 若同时提供 `note` 且 `len(基础标签) + len(note) + 3 <= 16`，拼装为 `"{基础标签} · {note}"`；否则仅展示基础标签（最终上限 `16` 字符）。
  - **建议**：若希望 `status` 与 `note` 同时展示，二者合计控制在 `<= 13` 字符。
- **独立有效期语义**：
  - 在 `0 <= now - updated_at <= stale_after_seconds` 期间，服务端在投影项中维持有效时间戳，终端保持彩色正常状态；
  - 超过 `stale_after_seconds` 后，服务端输出真实 `updated_at`，终端自动转为灰态并标注 `已过期`（保留最后一次数值，不自动归零）。
- **无自动衰减**：服务端不会在两次写入之间自动修改 `level_percent`；若需要随时间递减，需由上游定期重新计算并写入。

### 2.5 终端展示与同步边界
- **刷新延迟**：终端主动轮询 `GET /v1/display`（默认 60 秒一次），无 WebSocket 实时推送；写入后通常在 0–60 秒内生效。
- **单列布局**：所有显示端均为单列卡片，每页最多 6 项，超出自动分页轮播。
- **告警色阈值（由终端固定规则决定）**：
  - `>= 20%`：正常配色
  - `5%–19%`：警告黄
  - `< 5%`：警戒红（`0%` 无填充、红字）
  - `null`：灰态 `--`
- **来源展示**：非 `official` 来源（`manual` / `estimated` / `unknown`）会在卡片副行自动附加 `· 手动` / `· 估算` / `· 待接入`。

### 2.6 可选：接入服务端按需采集调度（拉模式边界）
- 若上游设计为拉取第三方 API 的服务端采集脚本，可复用 `server/display_push.py` 接入 `server/display_server.py` 的调度协议（详见 `server/COLLECTION_API.md`）：
  - 仅在有终端活跃读取（180 秒内有合法 `GET /v1/display`）时按 `600` 秒间隔下发采集租约（90 秒超时）；
  - 无人读取时自动暂停上游请求；
  - 采集失败不覆盖上次成功值，按 `600 / 1200 / 2400 / 3600` 秒指数退避。
- 若采用外部推送（如 iOS 快捷指令、外部定时任务、Bot），则不受服务端调度暂停规则限制，随时可调用 `PUT /v1/energy`。
